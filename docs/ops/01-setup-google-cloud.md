# Google Cloud OAuth Client ID 발급

## 목적
앱이 "구글로 로그인" 버튼을 띄우고, 로그인한 사용자의 이메일을 신뢰할 수 있게 하는 OAuth Client ID를 발급한다.

## 주의: 이 앱은 학생도 로그인한다 (출석부와의 차이)
참고한 출석부 앱은 교사만 로그인했다. 경건생활점검은 **찬양팀 학생 전원 + 교사**가 로그인 대상이라, "테스트 사용자" 방식으로는 인원 관리가 번거롭다.

이 앱이 요청하는 스코프는 `openid`, `email`, `profile` 세 가지뿐이며 이는 Google이 정의한 **비민감(non-sensitive) 스코프**다. 비민감 스코프만 쓰는 앱은:
- 앱 검증(verification) 절차 없이 **게시(Production)** 상태로 전환할 수 있다.
- 게시해도 "테스트 사용자" 100명 제한이 적용되지 않는다.
- 사용자에게 "확인되지 않은 앱" 경고 화면이 뜨지 않는다.

따라서 아래 절차는 **게시(권장)** 를 기본으로 안내하고, 대안으로 테스트 모드 유지 방법도 함께 적는다.

## 절차

1. https://console.cloud.google.com/ 접속, 본인 구글 계정으로 로그인.
2. 상단 프로젝트 선택 → "새 프로젝트" → 이름: `godly-life-check` (자유롭게 지정 가능).
3. 좌측 메뉴 → "API 및 서비스" → "사용자 인증 정보".
4. 상단 "OAuth 동의 화면 구성" 클릭.
   - User Type: **외부**
   - 앱 이름: `경건생활점검` (또는 원하는 이름)
   - 사용자 지원 이메일: 본인 이메일
   - 개발자 연락처: 본인 이메일
   - 범위(Scopes) 단계에서 추가 스코프를 넣지 않는다. GIS(Google Identity Services) 로그인 버튼이 기본으로 요청하는 `openid`/`email`/`profile`만 사용한다.
5. 동의 화면 저장 후, 게시 상태를 정한다. 둘 중 하나를 선택:
   - **(권장) 게시(Production)로 전환**: "앱 게시" 버튼 클릭 → 확인. 비민감 스코프만 쓰므로 검증 절차 없이 즉시 게시된다. 이후 학생·교사 전원이 별도 등록 없이 로그인 가능.
   - **(대안) 테스트 모드 유지**: "테스트 사용자" 섹션에 로그인할 학생·교사 전원의 구글 이메일을 등록한다(최대 100명). 인원이 바뀔 때마다(신입 학생, 이메일 변경 등) 이 목록을 직접 관리해야 한다는 부담이 있다. 찬양팀 인원이 적고 외부 공개를 피하고 싶다면 선택 가능.
6. 다시 "사용자 인증 정보" → "사용자 인증 정보 만들기" → "OAuth 클라이언트 ID".
   - 애플리케이션 유형: **웹 애플리케이션**
   - 이름: `godly-life-check-web`
   - **승인된 JavaScript 원본**:
     - `https://<github-user>.github.io` (GitHub Pages 도메인)
     - 커스텀 도메인을 쓸 경우 함께 등록
     - 로컬에서 테스트하려면 `http://localhost:<포트>`도 추가 가능(단, MOCK 모드에서는 GIS 로그인 자체를 스킵하므로 필수는 아님)
   - 승인된 리디렉션 URI: 사용 안 함 (GIS는 popup/FedCM 방식이라 리디렉션이 필요 없음)
7. 발급된 Client ID를 메모. 형식: `1234567890-abc...apps.googleusercontent.com`

## 출력
- `OAUTH_CLIENT_ID = ...` 1개. 이후 GAS Script Properties(`03-deploy-gas.md`)와 `web/index.html`의 `APP_CONFIG`(`04-deploy-github-pages.md`)에 동일한 값을 입력한다.
- 게시 상태(게시 vs 테스트)를 메모해 둔다. 테스트 모드를 선택했다면, 이후 학생이 추가될 때마다 이 콘솔로 돌아와 테스트 사용자 목록을 갱신해야 한다(`06-operations.md` 참고).
