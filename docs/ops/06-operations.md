# 운영 가이드

## 학생 추가

1. MEMBERS 시트에 새 행 추가: `email | 이름 | role | 파트 | active`
   - `email`: 학생의 구글 계정 이메일(정확히).
   - `role`: `student`
   - `파트`: 찬양팀 파트(선택).
   - `active`: 비워둔다(기본 활성).
2. `01-setup-google-cloud.md`에서 **테스트 모드**를 선택했다면, Google Cloud Console의 OAuth 동의 화면 → 테스트 사용자 목록에도 해당 학생 이메일을 추가해야 한다. **게시(Production) 상태**라면 이 단계는 필요 없다.
3. 학생에게 앱 URL을 안내하고, 처음 로그인 시 개인정보 안내(아래 "개인정보 유의" 참고)를 함께 전달한다.

## 학생 비활성 처리 (탈퇴, 휴학 등)

- MEMBERS 시트에서 해당 학생 행의 `active` 값을 `FALSE`로 바꾼다. 행 자체를 삭제하지 않는다.
- 비활성화해도 RECORDS에 남아 있는 과거 기록은 삭제되지 않고 유지된다. 다만 비활성 학생은 이후 로그인 시 `unauthorized`로 거부되어 새 기록을 남길 수 없다.
- "우리팀" 탭 조회에서도 비활성 학생은 목록에서 빠진다.
- 완전히 삭제하고 싶다면 MEMBERS 행과 함께 RECORDS의 해당 email 행들도 수동으로 지운다(되돌릴 수 없으니 신중히).

## 교사 추가/변경

- MEMBERS에 `role=teacher`(또는 `admin`) 행 추가. `파트`는 비워둬도 된다.
- v1 구조상 teacher/admin은 **활성 학생 전원**의 기록을 볼 수 있다(반별 분리 없음). 새 교사를 추가하면 그 즉시 전체 학생 기록에 접근 가능해지므로, 신뢰할 수 있는 인원만 등록한다.

## 수련회 이후 항목 조정

"수련회기도" 항목은 수련회가 끝난 뒤에는 의미가 없어질 수 있다. 이 항목은 계약(`docs/specs/2026-07-18-api-contract.md`)에 고정된 열이므로, 다음 중 하나로 대응한다:

- **문구만 바꾸는 방법**: `web/index.html`의 화면 라벨("수련회를 위한 기도" 등)만 다른 문구(예: "이번 주 기도 제목")로 바꾼다. 시트 헤더(`수련회기도`)와 API 필드명(`retreatPrayer`)은 그대로 둔다 — 헤더를 바꾸면 앱이 오동작한다.
- **기능 자체를 유지/비활성화**: 요구사항 목록(`CLAUDE.md`)에 없는 변경(체크박스 제거 등)은 임의로 하지 않는다. 필요하면 이 문서에 남기지 말고 총괄 에이전트/개발 담당에게 변경 요청으로 전달한다.
- 시즌이 지나도 기존 RECORDS 데이터의 `수련회기도` 열 값은 그대로 보존한다(과거 기록 훼손 금지).

## 개인정보 유의 — 반드시 학생에게 사전 고지

"와닿은말씀"과 "결단"은 학생이 적는 **신앙 고백성 텍스트**다. 다음 사실을 학생들에게 사용 시작 전 반드시 알린다:

- MEMBERS에 등록된 **교사 전원**이 "우리팀" 탭에서 학생 본인을 포함한 **활성 학생 전원**의 기록을 열람할 수 있다(담당 학생만 보는 구조가 아니다 — `docs/specs` §2 스코핑 규칙).
- 즉, 자신이 작성한 와닿은말씀·결단 텍스트는 등록된 모든 교사가 볼 수 있다는 점을 인지한 상태에서 작성하도록 안내한다.
- 시트 자체는 배포자 계정만 접근 가능하도록 유지한다(`02-setup-sheet.md`). 시트 공유를 늘리지 않는다.
- 학생·교사 퇴장(비활성 처리) 후에도 과거 텍스트는 시트에 남는다는 점도 함께 안내한다.

## 문제 해결 (에러 코드별)

앱 화면이나 브라우저 콘솔에 아래 코드가 보이면 다음을 확인한다.

| 코드 | 의미 | 확인할 것 |
|---|---|---|
| `no_token` | 로그인 토큰이 요청에 없음 | 로그인이 정상적으로 됐는지, sessionStorage에 토큰이 저장됐는지 브라우저 콘솔에서 확인 |
| `invalid_token` / `tokeninfo_failed` | 토큰 형식이 이상하거나 Google tokeninfo 검증 자체가 실패 | 네트워크 상태 확인, 토큰 문자열이 손상되지 않았는지 확인 |
| `aud_mismatch` | 토큰의 발급 대상(aud)이 서버가 기대하는 Client ID와 다름 | **가장 흔한 배포 실수.** `web/index.html`의 `APP_CONFIG.OAUTH_CLIENT_ID`와 GAS Script Properties의 `OAUTH_CLIENT_ID`가 **정확히 같은 값**인지 대조(`01-setup-google-cloud.md`에서 하나의 Client ID만 발급했는지, 다른 프로젝트의 ID를 잘못 넣지 않았는지 확인) |
| `iss_mismatch` | 토큰 발급자(iss)가 Google이 아님 | 정상적인 GIS 로그인 흐름을 우회했거나 토큰이 위조된 경우. 재로그인으로 해결되지 않으면 코드 점검 필요 |
| `token_expired` | 토큰 유효기간 만료 | 재로그인 유도(앱의 `app:session-expired` 처리가 정상 동작하는지 확인) |
| `email_unverified` | 구글 계정 이메일이 인증되지 않음 | 사용자에게 구글 계정의 이메일 인증 완료를 안내 |
| `unauthorized` | MEMBERS에 없거나 `active`가 비활성 | MEMBERS 시트에 해당 이메일이 정확히(오타 없이) 등록되어 있는지, `active` 값이 비활성 처리(`FALSE/NO/0/N`)되어 있지 않은지 확인 |
| `forbidden` | 권한 없는 액션 호출(예: 학생이 `getAllRecords` 호출) | 정상적인 방어 동작. 학생 계정에 교사 전용 탭이 노출되고 있다면 프론트 role 분기 버그이므로 코드 점검 필요 |
| `bad_request` | `setRecord`에 오늘·어제가 아닌 날짜를 보냄 | 프론트가 날짜 스테퍼로 오늘·어제 외 날짜를 허용하고 있지 않은지 확인. 기기 시각이 잘못 설정된 경우(시간대 오조정)도 원인이 될 수 있음 |
| `server_misconfig` | GAS Script Properties(`SHEET_ID`, `OAUTH_CLIENT_ID`) 누락 | `03-deploy-gas.md` 2단계를 다시 확인, 두 속성이 모두 등록됐는지 확인 |
| `server_error` | 그 외 서버 내부 오류(시트 접근 실패 등) | Apps Script IDE → 실행 로그(실행 기록)에서 스택 트레이스 확인. 시트 ID가 잘못됐거나 시트가 삭제/이동된 경우가 흔한 원인 |
| `unknown_action` | 존재하지 않는 액션 이름 호출 | 프론트·백엔드 배포 버전 불일치 가능성. `03-deploy-gas.md`의 재배포 절차대로 최신 코드로 갱신했는지 확인 |

### 저장은 되는데 화면에 반영이 안 될 때
- 프론트 인메모리 캐시(TTL 2분) 때문일 수 있다. `setRecord` 성공 시 `getMyRecords`/`getAllRecords` 캐시가 무효화되어야 정상이므로, 무효화 로직이 동작하는지 코드 점검이 필요할 수 있다. 새로고침으로 해결되면 캐시 만료 지연일 뿐 버그는 아니다.
- 서버 쪽 `getAllRecords` 캐시(CacheService, 5분)는 `setRecord` 호출 시 무효화되도록 설계되어 있다. 교사 화면에서 5분 넘게 반영이 안 되면 이 무효화가 실패한 것이므로 코드 점검 대상이다.

### 로그인 자체가 안 될 때
- 브라우저 콘솔에 `origin` 관련 오류(`redirect_uri_mismatch` 등)가 보이면 `04-deploy-github-pages.md` 5단계(승인된 JavaScript 원본)를 다시 확인한다.
- 테스트 모드로 운영 중인데 특정 사용자만 로그인 화면에서 막힌다면, 그 사용자의 이메일이 테스트 사용자 목록에 빠져 있을 가능성이 높다(`01-setup-google-cloud.md` 참고).
